# 位置/速度标定功能设计

## 背景

在现有轨道模拟工作台中新增“其他功能”区域，并在其中提供“位置/速度标定”功能。用户输入一个 ECI 位置矢量或 ECI 速度矢量后，系统在当前展示的所有可见轨道上查找满足该矢量的轨道状态点，并将精确命中的点标在主 3D 轨道场景中。

该功能不引入新的轨道模型。标定求解必须复用现有 `propagateOrbit(orbit, elapsedSeconds, { perturbationModel })`，因此二体、J2、J3 的语义与主 3D 场景保持一致。

## 已确认范围

- 匹配方式：精确求解。实现上采用“采样定位 + 数值精修”，只有残差低于内部精度阈值时才算命中。
- 输入坐标系：固定 ECI。
- 输入模式：二选一，用户在“位置标定”和“速度标定”之间切换，每次只按一种矢量求解。
- 求解范围：每条可见轨道的一整圈参考轨道。
- 动力学模型：跟随当前工作台选择的二体、J2 或 J3 模型。
- 展示位置：只在主 3D 轨道场景标出命中点，并在“其他功能”结果区列出命中信息。
- 无精确解：显示“无精确解”并给出最近点参考，但最近点不作为命中点标记。
- 标定结果保留：保留到下次标定或用户点击清除。

## 用户界面

工作台新增一个折叠面板“其他功能”。其中第一项为“位置/速度标定”，包含：

- 模式切换：`位置标定` / `速度标定`。
- ECI 矢量输入：`x`、`y`、`z` 三个数字输入框。
- 单位提示：位置模式显示 `km`，速度模式显示 `km/s`。
- 操作按钮：`标定`、`清除`。
- 结果区：显示当前模式、输入矢量、命中数量、命中列表或最近点参考。

点击“标定”后，系统对所有当前可见轨道进行求解。隐藏轨道不参与求解。点击“清除”后，清空结果区和 3D 标定标记。

结果列表中每个命中项显示：

- 轨道名称。
- 仿真时刻偏移，单位为秒。
- ECI 位置，单位为 `km`。
- ECI 速度，单位为 `km/s`。
- 残差。
- 当前动力学模型。

无精确命中时，结果区显示“无精确解”，并显示全部可见轨道中的最近点参考。最近点参考包含轨道名称、仿真时刻偏移、对应 ECI 状态和残差。

## 求解设计

新增纯计算模块 `js/vector-calibration.mjs`。该模块只处理数据，不访问 DOM，也不创建 Three.js 对象。

模块输入：

- 轨道记录数组。
- 标定模式：`position` 或 `velocity`。
- 目标矢量。
- 当前动力学模型。
- 采样预算。

模块输出：

- `hits`：精确命中的点。
- `nearest`：所有候选中的最近点参考。
- `mode`、`targetVector`、`perturbationModel`。
- 输入或求解错误信息。

求解流程：

1. 校验目标矢量三个分量都是有限数字。
2. 过滤出当前可见轨道。
3. 对每条轨道的 `0 ~ orbit.periodSeconds` 范围进行完整一圈采样。
4. 使用目标矢量与传播状态的对应矢量计算三维欧氏残差。
5. 找出残差的局部最小候选区间。
6. 对每个候选区间做一维数值优化，精修 `elapsedSeconds`。
7. 若精修残差低于内部阈值，将其记录为命中。
8. 对同一轨道中周期闭合或极近的重复命中去重。
9. 若没有命中，保留全局最近点作为参考。

内部精度阈值不作为首版 UI 控制项。位置标定阈值为 `max(1e-6 * scaleKm, 1e-3) km`，其中 `scaleKm` 取目标位置模长和轨道半长轴中的较大值；速度标定阈值为 `max(1e-7 * scaleKmS, 1e-6) km/s`，其中 `scaleKmS` 取目标速度模长和当前轨道速度量级中的较大值。结果区显示实际残差，让用户能判断输入与轨道状态的接近程度。

采样定位采用足够覆盖完整一圈的基础采样数，并随现有性能预算收缩或扩展。数值精修只在局部最小候选附近运行，避免对每条轨道进行昂贵的全局连续搜索。

## 3D 场景标记

`js/scene.mjs` 在现有轨道组之外新增一组标定标记。标记不改变当前轨道、尾迹、完整参考轨道和选中逻辑。

标记规则：

- 每个命中点显示为小球加环形光晕。
- 标记颜色沿用对应轨道颜色，并提高亮度以便与航天器当前 marker 区分。
- 标记使用与轨道参考线相同的 ECI 到场景坐标映射，确保始终贴在轨道线上；不单独做 ECEF 输入或 ECEF 求解。
- 标记保留到下一次标定或清除标定；清空场景、导入新轨道、隐藏或删除相关轨道、切换动力学模型时清除受影响的标定结果。
- 标记不参与轨道选择和轨道悬停提示，避免与现有交互混淆。

`OrbitScene` 增加公开方法 `setCalibrationMarkers(markers)`。`js/app.mjs` 将当前标定命中结果转换为场景标记数据后传入该方法。

## 应用状态与数据流

`js/app.mjs` 新增标定状态：

- `calibrationMode`：`position | velocity`。
- `calibrationVector`：当前输入矢量。
- `calibrationResult`：最近一次求解结果。

数据流：

1. 用户在“其他功能”中选择模式并输入矢量。
2. 点击“标定”。
3. `app.mjs` 调用 `vector-calibration.mjs`，传入当前可见轨道、当前动力学模型和目标矢量。
4. `app.mjs` 渲染结果区。
5. 若存在命中，`app.mjs` 调用 `scene.setCalibrationMarkers(...)`。
6. 若无命中，`app.mjs` 清空场景标记，只显示最近点参考。
7. 点击“清除”时，清空状态、结果区和 3D 标记。

标定结果不需要随仿真播放实时移动。它代表完整参考轨道上的状态点，而不是当前航天器时刻。

## 异常处理

- 目标矢量缺失、为空或包含非有限数字时，结果区显示输入错误，不运行求解。
- 当前没有可见轨道时，结果区显示“暂无可标定轨道”。
- 传播结果中出现 NaN 或 Infinity 时，该采样点被过滤，不参与命中和最近点判定。
- 若某条轨道无法产生有效候选点，该轨道在结果中跳过。
- 如果所有轨道都没有有效候选点，结果区显示“无有效轨道状态”。

## 测试计划

新增 `test/vector-calibration.test.mjs`：

- 校验位置矢量输入必须为有限数字。
- 校验速度矢量输入必须为有限数字。
- 对由 `propagateOrbit` 生成的真实位置状态进行位置标定，应返回对应轨道命中。
- 对由 `propagateOrbit` 生成的真实速度状态进行速度标定，应返回对应轨道命中。
- 对明显不在轨道上的矢量，应返回无精确解和最近点参考。
- 多轨道输入时，只对可见轨道求解。
- J2/J3 模型参数应传递到每次传播。
- 周期闭合处重复命中应去重。

扩展 `test/static-files.test.mjs`：

- 工作台存在“其他功能”面板。
- 面板中存在“位置/速度标定”标题。
- 存在位置/速度模式切换、三个矢量输入、标定按钮、清除按钮和结果区。
- `js/app.mjs` 导入并调用 `vector-calibration.mjs`。
- `js/scene.mjs` 暴露 `setCalibrationMarkers`。

扩展或新增场景测试：

- 标定标记数据能被转换为 Three.js 标记对象。
- 再次设置标记会释放旧标记资源。
- 清空标记后场景不保留旧标定对象。

浏览器 QA：

- 添加一条轨道，用该轨道某个传播状态的位置矢量做位置标定，场景出现命中点。
- 用同一轨道某个传播状态的速度矢量做速度标定，场景出现命中点。
- 添加第二条可见轨道，标定会对两条轨道都求解。
- 隐藏轨道后，该轨道不参与标定。
- 输入无解矢量时，场景不显示命中点，结果区显示最近点参考。
- 点击清除后，结果和场景标记都消失。
- 切换 J2/J3 后重新标定，结果使用当前模型。

## 不在本次范围

- 不做位置与速度同时约束。
- 不做 ECEF 输入。
- 不做用户可配置容差。
- 不把标定点同步到星下点地图。
- 不做导出 CSV 或 PNG 的标定结果专用导出。
