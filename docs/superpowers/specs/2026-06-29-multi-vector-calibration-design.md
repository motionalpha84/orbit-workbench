# 多 ECI 矢量标定优化设计

## 背景

现有“其他功能 / 位置/速度标定”支持一次输入一个 ECI 位置矢量或速度矢量，并在当前可见轨道上查找精确命中点。用户测试后确认该基础功能满足需求，下一步需要支持多个 ECI 矢量同时标定，并允许为每个 ECI 矢量命名。

本优化在现有单矢量求解能力之上扩展批量输入、批量求解、分组展示和命名标记，不改变轨道动力学模型、坐标系或精确求解语义。

## 已确认范围

- 多矢量输入方式：采用表格行模式。
- 每一行代表一个标定目标。
- 每个 ECI 矢量各自拥有名称。
- 每个 ECI 矢量可以单独选择标定类型：位置或速度。
- 单个 ECI 矢量计算出的所有命中点共享该矢量名称。
- 结果区按矢量名称分组展示。
- 3D 场景中的命中标记附带该矢量名称。
- 清除结果时清空结果和 3D 标记，但保留用户已输入的矢量行。

## 用户界面

“位置/速度标定”工具从单个 `x/y/z` 输入升级为紧凑表格。每一行包含：

- 名称。
- 类型：位置或速度。
- `x`、`y`、`z` 三个 ECI 分量。
- 删除按钮。

工具区操作按钮：

- `添加矢量`：新增一行，默认名称为 `标定1`、`标定2` 等，默认类型为位置。
- `标定全部`：对所有可求解行执行标定。
- `清除结果`：清空结果区和 3D 标记，保留输入行。

结果区按目标矢量分组。每组显示：

- 矢量名称。
- 标定类型。
- 输入矢量与单位。
- 命中数量，或“无精确解”。
- 命中列表或最近点参考。

命中项继续显示：

- 轨道名称。
- 仿真时刻偏移，单位为秒。
- ECI 位置，单位为 `km`。
- ECI 速度，单位为 `km/s`。
- 残差。
- 当前动力学模型。

若一个命名矢量在多条可见轨道上命中多个点，这些命中点在同一结果组中展示，并共享该矢量名称。

## 数据模型

`js/app.mjs` 中的标定状态从单个矢量升级为目标列表：

```js
calibrationTargets: [
  {
    id: 'stable-id',
    name: '近地点速度',
    mode: 'velocity',
    vector: { x: '-0.926189', y: '3.706055', z: '-2.098647' },
  },
]
```

目标字段语义：

- `id`：稳定行标识，用于 DOM 渲染、删除和结果关联。
- `name`：用户填写的矢量名称。该名称用于结果分组和 3D 标记标签。
- `mode`：`position` 或 `velocity`，每行独立。
- `vector`：用户输入的 ECI 三维分量，保留为字符串直到求解阶段校验。

标定结果从单个 `calibrationResult` 升级为批量结果：

```js
calibrationResult: {
  status: 'complete',
  targets: [
    {
      targetId: 'stable-id',
      targetName: '近地点速度',
      mode: 'velocity',
      result: {
        status: 'hit',
        hits: [],
        nearest: null,
      },
    },
  ],
}
```

`result` 复用现有单矢量求解结果结构，以减少核心算法改动。

## 求解设计

保留现有 `calibrateOrbitVectors(records, options)` 作为单目标求解器。新增批量封装函数：

```js
calibrateOrbitVectorTargets(records, {
  targets,
  perturbationModel,
  sampleCount,
})
```

批量函数职责：

1. 遍历目标列表。
2. 校验每个目标的名称、模式和矢量。
3. 对有效目标调用现有 `calibrateOrbitVectors(...)`。
4. 将每个目标的名称、模式和单目标结果合并为分组结果。
5. 单个目标输入错误只影响该目标，不阻断其他目标继续求解。
6. 汇总全部精确命中点，供 3D 场景标记使用。

单目标求解器继续负责：

- 可见轨道过滤。
- 一整圈采样。
- 局部最小值定位。
- 数值精修。
- 残差阈值判定。
- 最近点参考。
- 周期重复命中去重。

## 3D 场景标记

`js/scene.mjs` 继续通过 `setCalibrationMarkers(markers)` 接收标记数据。标记数据新增目标字段：

```js
{
  targetId: 'stable-id',
  targetName: '近地点速度',
  orbitId: 'orbit-id',
  orbitName: 'QA-MEO-2',
  color: '#7fd1c7',
  positionKm: { x: 1, y: 2, z: 3 },
  residual: 0,
  elapsedSeconds: 120,
}
```

场景中的标记仍沿用轨道颜色。若显示标签或悬停文本，优先使用 `targetName`，并可组合轨道名和仿真时刻区分同名目标或多命中点。

无精确解的目标不生成 3D 标记，只在结果区显示最近点参考。

## 异常处理

- 名称为空：该行不运行求解，结果组显示“名称不能为空”。
- `x/y/z` 缺失或非有限数字：该行不运行求解，结果组显示输入错误。
- 某一行输入错误不影响其他有效行。
- 没有任何有效目标：结果区显示“暂无可标定矢量”。
- 多个目标同名：允许求解；结果按行分别展示，并保留相同名称。UI 可提示重名以降低混淆，但不阻止标定。
- 某个目标无精确解：该组显示“无精确解”和最近点参考，不生成 3D 标记。
- 当前没有可见轨道：每个有效目标返回“暂无可标定轨道”。
- 切换动力学模型、隐藏或删除轨道、导入轨道、清空场景、重置仿真时刻时，清除已有结果和 3D 标记，但保留用户输入的目标行。

## 数据流

1. 用户在表格中添加一个或多个标定目标。
2. 用户为每行填写名称、类型和 ECI 矢量。
3. 用户点击“标定全部”。
4. `app.mjs` 读取表格行，构造 `calibrationTargets`。
5. `app.mjs` 调用 `calibrateOrbitVectorTargets(...)`。
6. 批量求解器逐行调用现有单目标求解器。
7. `app.mjs` 按目标名称和目标行渲染结果分组。
8. `app.mjs` 将所有精确命中点转换为 3D markers，传给 `scene.setCalibrationMarkers(...)`。
9. 用户点击“清除结果”时，清空结果和 markers，保留表格行。

## 测试计划

扩展 `test/vector-calibration.test.mjs`：

- 批量求解多个目标，其中一个位置目标和一个速度目标均能命中。
- 单个目标命中多个轨道点时，所有命中点携带同一个 `targetName`。
- 某个目标输入错误时，其他目标继续求解。
- 没有有效目标时返回可渲染的空状态。
- 多个同名目标允许求解，并通过 `targetId` 保持结果独立。

扩展 `test/scene-calibration.test.mjs`：

- 标定 marker 标准化时保留 `targetId` 和 `targetName`。
- 缺失 `targetName` 时使用合理默认名称。

扩展 `test/static-files.test.mjs`：

- UI 包含多矢量表格容器。
- UI 包含添加矢量、标定全部、清除结果按钮。
- 行内包含名称输入、类型选择和三维分量输入。
- `app.mjs` 使用 `calibrationTargets` 状态。
- `app.mjs` 调用批量求解函数。
- 结果渲染支持按目标分组。

浏览器 QA：

- 添加两个目标：一个位置目标、一个速度目标。
- 分别填写名称和当前计算输出中的 ECI 位置/速度。
- 点击“标定全部”，两个结果组分别命中。
- 场景中显示所有命中点标记。
- 将其中一行改为无解矢量，该行显示“无精确解”，另一行仍命中。
- 输入错误只影响对应行。
- 点击“清除结果”，结果和 3D 标记消失，表格行仍保留。

## 不在本次范围

- 不做位置与速度同时约束。
- 不做 ECEF 输入。
- 不做用户可配置容差。
- 不做 CSV、JSON 或图片导出。
- 不把标定结果同步到星下点地图。
- 不实现复杂批量文本导入；表格输入是本次唯一输入方式。
